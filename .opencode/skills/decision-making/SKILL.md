# Purpose

This skill ensures that every technical decision is made systematically, objectively, and consistently with the project's goals and documented decisions.

The objective is not to find any solution, but the most appropriate solution for this project.

---

# When to Use

Use this skill whenever:

- Multiple implementation approaches exist.
- Choosing between technologies or libraries.
- Evaluating architectural alternatives.
- Making design decisions.
- Prioritizing implementation strategies.
- Resolving trade-offs.
- Selecting between different technical solutions.

Do not use this skill for implementation or debugging.

---

# Decision Workflow

Follow these steps.

## 1. Define the decision

Clearly identify:

- The problem.
- The available options.
- The desired outcome.

---

## 2. Gather constraints

Identify:

- Project requirements.
- Technical limitations.
- Existing architectural decisions.
- Documentation constraints.
- User requirements.

Never ignore existing project decisions.

---

## 3. Evaluate alternatives

For every option evaluate:

- Advantages.
- Disadvantages.
- Risks.
- Complexity.
- Long-term maintainability.
- Compatibility with the existing system.

---

## 4. Recommend the best option

Recommend only one option whenever possible.

Justify the recommendation using objective reasoning.

---

## 5. Identify uncertainty

If insufficient information exists:

- Explain why.
- Request clarification.

Never guess.

---

# Mandatory Rules

Always:

- Prefer the simplest solution that satisfies the requirements.
- Respect documented project decisions.
- Consider long-term maintainability.
- Explain trade-offs.
- Separate facts from opinions.

Never:

- Assume requirements.
- Ignore documented constraints.
- Recommend unnecessary complexity.
- Prefer novelty over stability.

---

# Expected Output

Every decision must include:

## Problem

## Available Options

## Evaluation

## Recommendation

## Justification

## Missing Information (if applicable)
