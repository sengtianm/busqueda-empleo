# Purpose

This skill ensures that project documentation is always treated as the primary source of truth before making implementation or design decisions.

Documentation takes precedence over assumptions, memory, or previous conversations.

---

# When to Use

Use this skill whenever:

- Answering questions about the project.
- Making implementation decisions.
- Reviewing existing functionality.
- Planning new work.
- Explaining system behavior.
- Resolving ambiguities.
- Looking for project-specific information.

Do not use this skill for general programming questions unrelated to this project.

---

# Documentation Workflow

Follow these steps.

## 1. Determine whether documentation is required

Ask yourself:

- Is this project-specific?
- Does documentation probably contain the answer?

If yes, consult the documentation first.

---

## 2. Locate the relevant documentation

Identify every document related to the request.

Never rely on only one document if multiple documents are applicable.

---

## 3. Read before deciding

Understand the relevant documentation completely before making conclusions.

Never answer based only on memory.

---

## 4. Resolve conflicts

If documentation appears inconsistent:

- Identify the conflict.
- Explain it.
- Request clarification.

Never choose one interpretation arbitrarily.

---

## 5. Separate facts from assumptions

Clearly distinguish:

- Documented facts.
- Reasonable inferences.
- Unknown information.

Never present assumptions as facts.

---

# Mandatory Rules

Always:

- Treat documentation as authoritative.
- Prefer documented decisions over assumptions.
- Read all relevant documents before answering.
- Explain when documentation does not contain the answer.
- Preserve consistency with previous documented decisions.

Never:

- Invent project rules.
- Ignore documentation.
- Contradict documented decisions.
- Fill missing information without asking.
- Override documentation using general knowledge.

---

# Expected Output

Every response should indicate:

## Documentation Used

Which project documents were consulted.

## Conclusion

Answer supported by documentation.

## Assumptions

Explicitly identify any assumptions.

## Missing Information

Describe anything that requires clarification before continuing.
